# socle-web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dépôt modèle Next.js/TypeScript qui applique les bonnes pratiques DevOps du cours CDA (Git, CI, tests, Docker, sécurité), documenté en français.

**Architecture:** Application Next.js minimale (une page, une route `/api/health`), sortie `standalone` empaquetée dans une image Docker non-root. Trois workflows GitHub Actions (ci, security, release) + Dependabot. Conventions Git outillées par un hook local et un ruleset versionné.

**Tech Stack:** Node 24, pnpm 10, Next.js (dernière stable), TypeScript strict, Vitest + @vitest/coverage-v8, ESLint (flat config), Prettier, Docker, GitHub Actions, Trivy, gitleaks, Semgrep, CodeQL.

**Spec:** `docs/superpowers/specs/2026-11-17-socle-web-design.md`

## Global Constraints

- Dépôt : `/Volumes/SSD-JB/Dev/socle-web` (git déjà initialisé, branche `main`, aucun commit). Tout le travail se fait sur `main` en local.
- Commits : Conventional Commits, type anglais + description française (`feat: ajoute la route de santé`). Jamais de mention de Claude, jamais de `Co-Authored-By`. Pas d'emoji.
- Node 24 (`.nvmrc` = `24`, `engines.node` = `>=24`), `packageManager` = `pnpm@10.33.0`.
- TypeScript `strict: true`. Zéro erreur `pnpm typecheck`, `pnpm lint`, `pnpm format:check`.
- Couverture Vitest : seuil bloquant 80 % des lignes.
- Toute action GitHub épinglée par SHA complet de 40 caractères + commentaire `# vX.Y.Z`. Résoudre les SHA avec `gh api repos/<owner>/<repo>/commits/<tag> -q .sha` (donne le SHA du commit, même pour un tag annoté).
- Workflows : `permissions: {}` au niveau workflow, droits minimaux par job ; `timeout-minutes` sur chaque job ; `concurrency` qui annule sur PR et jamais sur `main` ; aucun `${{ ... }}` d'entrée utilisateur dans un `run:` (passer par `env:`) ; `pnpm install --frozen-lockfile`.
- Noms de jobs CI stables (ils deviennent des checks requis du ruleset) : `qualite`, `tests`, `build`, `docker`, `actionlint`.
- Images de base en tag précis (`node:24.x-alpine` avec numéro mineur), jamais `latest`.
- Docs et commentaires en français, avec accents.
- Sorties d'outils filtrées (`| tail -20`) dans tes vérifications : pas de logs entiers.

## Review Focus

- `APP_VERSION` absent : `/api/health` doit répondre `version: "dev"`, pas `undefined` (test dans Task 1).
- Conteneur lancé : doit tourner sous un utilisateur non-root et le HEALTHCHECK doit passer à `healthy` (vérifié Task 2).
- Message de commit non conforme (`update stuff`, `Feat: x`, type inconnu) : le hook refuse ; `Merge ...` et `Revert ...` générés par git passent (test du hook Task 3).
- PR qui ne touche que la doc : la CI doit quand même produire les checks requis (pas de filtre `paths` sur `pull_request`) (Task 4).
- Fork qui ouvre une PR : aucun job n'a de droit d'écriture ni accès à un secret (Task 4, revue des `permissions`).
